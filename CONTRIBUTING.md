# Contributing to ESP32 C Curriculum

Thank you for your interest in contributing to **ESP32 C Curriculum: From Bits to Networks**.

This project is a free, open-source educational curriculum designed to teach ESP32 development using **ESP-IDF**, **C**, and a smooth, linear learning path. The main goal is to make embedded learning easier, clearer, and less overwhelming for beginners.

Contributions are very welcome. If you think something can be explained better, simplified, corrected, or expanded in a way that helps learners, please feel free to contribute.

---

## Contribution Philosophy

This repository is not just a collection of ESP32 examples. It is a structured teaching path.

Every contribution should support these goals:

- Keep the learning curve **gentle and linear**
- Introduce only **one or two new concepts per project**
- Explain the “why”, not just the “how”
- Keep examples standalone and easy to build
- Prefer clarity over cleverness
- Use ESP-IDF and embedded C best practices
- Avoid confusing beginners with unnecessary complexity

If a change makes the project more correct but much harder to understand, it may need to be simplified or moved to an advanced/optional section.

---

## Ways to Contribute

You can contribute in many ways:

### Beginner-friendly improvements

- Fix spelling or grammar mistakes
- Improve explanations
- Simplify confusing sections
- Add beginner notes
- Improve README files
- Add common mistakes and troubleshooting tips

---

### Code improvements

- Fix bugs
- Improve comments
- Refactor code for clarity
- Improve error handling
- Update code for newer ESP-IDF versions
- Add build warnings or safety checks
- Keep examples consistent across projects

---

### Theory improvements

- Improve LaTeX files
- Rewrite explanations more clearly
- Add diagrams inside theory PDFs
- Improve formatting and readability
- Translate theory content into other languages, if a translation structure is added later

---

### Hardware and diagrams

- Improve wiring diagrams
- Add missing pin labels
- Create cleaner schematics
- Add photos or visual references
- Improve hardware BOM
- Add notes about compatible sensors and modules

---

### Videos

- Add explanatory videos
- Improve video descriptions
- Add timestamps
- Add transcripts or captions
- Link videos to the correct project README

---

### New lessons or extensions

New lessons are welcome, but they must fit the curriculum philosophy.

A good new lesson should:

- Fit naturally into the existing linear order
- Introduce only a small number of new concepts
- Build on previous projects
- Be useful on its own
- Include code, explanation, and hardware instructions
- Avoid jumping too far ahead of earlier material

If you want to add a completely new topic, please open an issue first to discuss where it belongs.
